## What belongs where

- **A design decision** — why the crates are split this way, where state lives, what "plugin" means —
  goes in `design/`, and it is a claim about the code, so it changes in the same commit as the code.
- **A how-to** — the catalog format, the bulk-data table — goes in `guides/`, and it is written for a
  reader who is about to do the thing.
- **A rule that a task enforces** goes in `standards.md`, with the task named. A rule with no
  enforcing task is a wish, and the rule book says so.
- **Generated text** goes in `api/`, is never edited by hand, and `cargo xtask api-docs check` fails
  when it is stale.
- **A plan** goes in `plans/` with its date in the file name. Plans are history: they are not updated
  after they land, and a reader who wants the current truth reads `design/`.

Everything here is written in English (the interface is translated; the engineering record is not).
See `standards.md` §9 for the repository layout as a whole.
