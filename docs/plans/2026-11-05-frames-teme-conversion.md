# TEME frame conversion implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the TEME state vectors `stkcraft-astro-sgp4` produces into ICRF and Earth-fixed
states, so a propagated satellite has a position something else can use.

**Architecture:** `stkcraft-astro-frames` gains four layers of increasing scope, each independently
testable against a published reference: fundamental arguments and the IAU-80 nutation series
(no frame objects yet, just numbers); precession and nutation *matrices*; sidereal time and the
composite TEME→GCRF and TEME→ITRF rotations; and finally a `TerrestrialFrame` type that owns the
Earth-orientation parameters and exposes the two conversions the rest of the product needs.
Nothing here invents a convention: every matrix is checked against two independent published
implementations, and every acceptance test names the reference value it reproduces.

**Tech Stack:** Rust 2024, `stkcraft-framework-core` (`Vector3`, `Result`), `stkcraft-framework-time` (`Epoch`,
`JulianDate`, `TimeScale`), `stkcraft-astro-sgp4` (`StateVector`). No new dependencies.

## Global Constraints

- **No panics in non-test code.** No `unwrap()`, `expect()`, `panic!`, `unreachable!`,
  `todo!`, `unimplemented!`; no `unsafe`. `crates/frames/src/lib.rs` already carries the
  `#![deny(...)]` block and `#![forbid(unsafe_code)]`; keep them.
- Test modules carry `#[cfg(test)] #[expect(clippy::expect_used, clippy::panic)]` because the
  deny applies to test targets too.
- **Every physical constant and formula cites its source in a comment.** Sources for this arc:
  Vallado, *Fundamentals of Astrodynamics and Applications*, 4th ed. (2013), sections 3.5–3.7
  and Algorithms 16–30; Seidelmann (ed.), *Explanatory Supplement to the Astronomical Almanac*
  (1992), section 3.222, for the IAU-80 nutation series; IERS Conventions (2010), chapters 5
  and 8, for the Earth-orientation parameters.
- **Clean-room.** The reference values below were generated by compiling public code:
  Vallado's `AstroLib` (`celestrak.org/software/vallado/cpp.zip`) and the IAU-80 coefficient
  table from ERFA (`liberfa/erfa`, BSD-3-Clause, derived from SOFA). **No code is copied**:
  the tables and series are published standards, and the Rust is written from the formulas.
  Never copy GPL/LGPL/AGPL code.
- **Nothing is added to `assets/`**, so `ATTRIBUTION.md` needs no row. The scratch `.refdata/`
  download **must be deleted before committing**; `cargo xtask assets` fails if it is not,
  which is the intended guard.
- `cargo xtask ci --offline` must pass all six gates before every commit, and every commit's
  message states Why / What changed / Verification / Known gaps.
- **Never run `cargo` without `--offline`** in this environment.
- Units are types at public boundaries. Internally, series arguments are radians in `f64` with
  the unit named in the variable.

//! The Delaunay fundamental arguments the IAU-80 nutation series is written in.
//!
//! Source: Seidelmann (ed.), *Explanatory Supplement to the Astronomical Almanac* (1992),
//! section 3.222, p111, which defines the IAU-80 series. The polynomial form below is the one
//! ERFA uses in `eraNut80` (`src/nut80.c`) and Vallado uses in `AstroLib.cpp :: fundarg` for
//! the 1980 theory; both were checked against each other and their coefficients are identical.
//!
//! Each argument is a polynomial in Julian centuries of TT plus a whole-revolution term taken
//! separately. That split is not cosmetic: it keeps the large integer part of `1325 * t`
//! exact, so the fractional precision of the polynomial is not destroyed by adding it to a
//! number of order 1e4 arcseconds.

use stkcraft_framework_core::{Error, Result};

/// Arcseconds to radians, `pi / (180 * 3600)`.
const ARCSEC_TO_RAD: f64 = core::f64::consts::PI / 648_000.0;

/// One revolution in radians.
const TAU: f64 = core::f64::consts::TAU;

/// The five Delaunay fundamental arguments the IAU-80 nutation series needs, radians.
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct FundamentalArguments {
    /// Mean longitude of the Moon minus mean longitude of the Moon's perigee (`l`).
    pub moon_mean_longitude: f64,
    /// Mean longitude of the Sun minus mean longitude of the Sun's perigee (`l'`).
    pub sun_mean_longitude: f64,
    /// Mean longitude of the Moon minus mean longitude of the Moon's node (`F`).
    pub moon_argument_of_latitude: f64,
    /// Mean elongation of the Moon from the Sun (`D`).
    pub moon_elongation: f64,
    /// Longitude of the mean ascending node of the lunar orbit (`Omega`).
    pub moon_node_longitude: f64,
}

/// Fold an angle into `(-pi, pi]`.
///
/// This is ERFA's `eraAnpm`. A plain `%` is not enough: it leaves the result with the sign of
/// the dividend, so an angle just below zero becomes `-pi` rather than `+pi`.
fn normalise(angle: f64) -> f64 {
    let wrapped = angle % TAU;
    if wrapped.abs() >= core::f64::consts::PI {
        wrapped - TAU.copysign(angle)
    } else {
        wrapped
    }
}

/// Fundamental arguments from the IERS 1980 (IAU-80) expressions.
///
/// # Errors
///
/// Returns [`Error::Invalid`] for a non-finite time, so a NaN can never reach the series.
pub fn iau_1980(ttt: f64) -> Result<FundamentalArguments> {
    if !ttt.is_finite() {
        return Err(Error::invalid("Julian centuries of TT", "must be finite"));
    }

    // `(c0 + (c1 + (c2 + c3 t) t) t)` arcseconds, plus a whole-revolution term.
    let moon_mean_longitude = normalise(
        (485_866.733 + (715_922.633 + (31.310 + 0.064 * ttt) * ttt) * ttt) * ARCSEC_TO_RAD
            + (1_325.0 * ttt).fract() * TAU,
    );
    let sun_mean_longitude = normalise(
        (1_287_099.804 + (1_292_581.224 + (-0.577 - 0.012 * ttt) * ttt) * ttt) * ARCSEC_TO_RAD
            + (99.0 * ttt).fract() * TAU,
    );
    let moon_argument_of_latitude = normalise(
        (335_778.877 + (295_263.137 + (-13.257 + 0.011 * ttt) * ttt) * ttt) * ARCSEC_TO_RAD
            + (1_342.0 * ttt).fract() * TAU,
    );
    let moon_elongation = normalise(
        (1_072_261.307 + (1_105_601.328 + (-6.891 + 0.019 * ttt) * ttt) * ttt) * ARCSEC_TO_RAD
            + (1_236.0 * ttt).fract() * TAU,
    );
    let moon_node_longitude = normalise(
        (450_160.280 + (-482_890.539 + (7.455 + 0.008 * ttt) * ttt) * ttt) * ARCSEC_TO_RAD
            + (-5.0 * ttt).fract() * TAU,
    );

    Ok(FundamentalArguments {
        moon_mean_longitude,
        sun_mean_longitude,
        moon_argument_of_latitude,
        moon_elongation,
        moon_node_longitude,
    })
}
```

```rust
//! The IAU-80 nutation series.
//!
//! Source: Seidelmann (ed.), *Explanatory Supplement to the Astronomical Almanac* (1992),
//! section 3.222, p111. The 106-term table is transcribed from ERFA `src/nut80.c`
//! (BSD-3-Clause), itself derived from the SOFA library, and is identical to the table
//! Vallado uses in `AstroLib.cpp :: nutation`; the two implementations agree to 3e-15 rad.
//!
//! Coefficients are in units of 0.1 milliarcsecond, and their `t` terms in 0.1 mas per Julian
//! century.

use stkcraft_framework_core::{Error, Result};

use crate::arguments::iau_1980 as fundamental_arguments;

/// Arcseconds to radians.
const ARCSEC_TO_RAD: f64 = core::f64::consts::PI / 648_000.0;

/// The coefficients are in tenths of a milliarcsecond.
const TENTH_MAS_TO_RAD: f64 = ARCSEC_TO_RAD / 1e4;

/// One row of the IAU-80 series.
///
/// The first five fields are integer multiples of the Delaunay arguments `l`, `l'`, `F`, `D`
/// and `Omega`. The last four are `delta psi` sine coefficients (constant and per century) and
/// `delta epsilon` cosine coefficients (constant and per century), in 0.1 mas.
const TABLE: [(i8, i8, i8, i8, i8, f64, f64, f64, f64); 106] = [
    // ... the 106 rows generated in Step 3 ...
];

/// Nutation in longitude and obliquity, radians.
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct Nutation {
    /// Nutation in longitude, `delta psi`.
    pub longitude: f64,
    /// Nutation in obliquity, `delta epsilon`.
    pub obliquity: f64,
}

/// The mean obliquity of the ecliptic, radians.
///
/// Source: Seidelmann (ed.), Explanatory Supplement (1992), section 3.222, the IAU-80
/// expression `84381.448" - 46.8150" t - 0.00059" t^2 + 0.001813" t^3`.
///
/// # Errors
///
/// Returns [`Error::Invalid`] for a non-finite time.
pub fn mean_obliquity(ttt: f64) -> Result<f64> {
    if !ttt.is_finite() {
        return Err(Error::Invalid {
            what: "Julian centuries of TT",
            reason: "must be finite".to_owned(),
        });
    }
    let arcsec = 84_381.448 + (-46.8150 + (-0.000_59 + 0.001_813 * ttt) * ttt) * ttt;
    Ok(arcsec * ARCSEC_TO_RAD)
}

/// The IAU-80 nutation series, radians.
///
/// The terms are summed from the last to the first so that the large `Omega` term is added
/// last. That is the order the published series is written in and the order ERFA uses; summing
/// the other way changes the answer in the last few bits, which shows up when comparing
/// against a reference table to fifteen digits.
///
/// # Errors
///
/// Returns [`Error::Invalid`] for a non-finite time.
pub fn iau_1980(ttt: f64) -> Result<Nutation> {
    let a = fundamental_arguments(ttt)?;

    let mut delta_psi = 0.0_f64;
    let mut delta_eps = 0.0_f64;
    for &(nl, nlp, nf, nd, nom, sp, spt, ce, cet) in TABLE.iter().rev() {
        let argument = f64::from(nl) * a.moon_mean_longitude
            + f64::from(nlp) * a.sun_mean_longitude
            + f64::from(nf) * a.moon_argument_of_latitude
            + f64::from(nd) * a.moon_elongation
            + f64::from(nom) * a.moon_node_longitude;
        let sine = sp + spt * ttt;
        let cosine = ce + cet * ttt;
        if sine != 0.0 {
            delta_psi += sine * argument.sin();
        }
        if cosine != 0.0 {
            delta_eps += cosine * argument.cos();
        }
    }

    Ok(Nutation {
        longitude: delta_psi * TENTH_MAS_TO_RAD,
        obliquity: delta_eps * TENTH_MAS_TO_RAD,
    })
}
```

//! IAU-77 precession, which takes the mean equator and equinox of date to the mean equator
//! and equinox of J2000 (MOD to GCRF).
//!
//! Source: Vallado, *Fundamentals of Astrodynamics and Applications* (2013), section 3.7 and
//! eq. 3-56 through 3-58. This is the IAU-77 theory, the one the reference implementation
//! selects with `opt == e80`, and the one that belongs with the IAU-80 nutation series in
//! `crate::nutation`.

use stkcraft_framework_core::{Error, Result};

use crate::rotation::Rotation3;

/// Arcseconds to radians.
const ARCSEC_TO_RAD: f64 = core::f64::consts::PI / 648_000.0;

/// The three IAU-77 precession angles, radians.
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct PrecessionAngles {
    /// `zeta`, the accumulated precession in right ascension at the moving equinox.
    pub zeta: f64,
    /// `theta`, the accumulated precession in declination.
    pub theta: f64,
    /// `z`, the accumulated precession in right ascension at the fixed equinox.
    pub z: f64,
}

/// The IAU-77 precession angles for `ttt` Julian centuries of TT.
///
/// # Errors
///
/// Returns [`Error::Invalid`] for a non-finite time.
pub fn iau_1977_angles(ttt: f64) -> Result<PrecessionAngles> {
    if !ttt.is_finite() {
        return Err(Error::Invalid {
            what: "Julian centuries of TT",
            reason: "must be finite".to_owned(),
        });
    }
    Ok(PrecessionAngles {
        zeta: ((0.017_998 * ttt + 0.301_88) * ttt + 2306.2181) * ttt * ARCSEC_TO_RAD,
        theta: ((-0.041_833 * ttt - 0.426_65) * ttt + 2004.3109) * ttt * ARCSEC_TO_RAD,
        z: ((0.018_203 * ttt + 1.094_68) * ttt + 2306.2181) * ttt * ARCSEC_TO_RAD,
    })
}

/// The rotation taking mean-of-date to mean-of-J2000 (MOD to GCRF).
///
/// The matrix is written out rather than composed from three axis rotations. That is how the
/// published reference forms it: the closed form saves two multiplications and, more
/// importantly, the rounding they carry, which is visible at the fifteenth digit — the
/// precision the reference table is compared at.
///
/// # Errors
///
/// Returns [`Error::Invalid`] for a non-finite time, or if the angles produce a matrix that
/// is not a proper rotation (which can only happen for a time outside the theory's range).
pub fn iau_1976_matrix(ttt: f64) -> Result<Rotation3> {
    let PrecessionAngles { zeta, theta, z } = iau_1977_angles(ttt)?;
    let (sin_zeta, cos_zeta) = zeta.sin_cos();
    let (sin_theta, cos_theta) = theta.sin_cos();
    let (sin_z, cos_z) = z.sin_cos();

    Rotation3::from_rows([
        [
            cos_zeta * cos_theta * cos_z - sin_zeta * sin_z,
            cos_zeta * cos_theta * sin_z + sin_zeta * cos_z,
            cos_zeta * sin_theta,
        ],
        [
            -sin_zeta * cos_theta * cos_z - cos_zeta * sin_z,
            -sin_zeta * cos_theta * sin_z + cos_zeta * cos_z,
            -sin_zeta * sin_theta,
        ],
        [-sin_theta * cos_z, -sin_theta * sin_z, cos_theta],
    ])
}

```rust
//! Greenwich mean sidereal time.
//!
//! Sidereal time is the Earth's rotation angle measured against the stars rather than the Sun,
//! and it is what turns a TEME position into an Earth-fixed one.
//!
//! Source: Vallado, *Fundamentals of Astrodynamics and Applications* (2013), eq. 3-45, the
//! IAU-82 expression, as implemented by the reference `gstime` routine:
//!
//! ```text
//! tut1  = (jdut1 - 2451545.0) / 36525
//! gmst  = -6.2e-6 tut1^3 + 0.093104 tut1^2 + (876600*3600 + 8640184.812866) tut1 + 67310.54841  [s]
//! theta = (gmst mod 86400) / 240 degrees, normalised into [0, 360)
//! ```
//!
//! The `876600 * 3600` term is the whole turns the Earth has made since J2000; it is kept
//! because the reduction to `[0, 2pi)` afterwards is exact and the expression then matches the
//! published one term for term.

use stkcraft_framework_core::{Error, Result};

/// Seconds in a day, for the modulo.
const SECONDS_PER_DAY: f64 = 86_400.0;

/// Degrees to radians.
const DEG_TO_RAD: f64 = core::f64::consts::PI / 180.0;

/// GMT at a UT1 Julian Date.
///
/// # Errors
///
/// Returns [`Error::Invalid`] for a non-finite date.
pub fn greenwich_mean(jdut1: f64) -> Result<f64> {
    if !jdut1.is_finite() {
        return Err(Error::Invalid {
            what: "UT1 Julian Date",
            reason: "must be finite".to_owned(),
        });
    }

    let tut1 = (jdut1 - 2_451_545.0) / 36_525.0;
    let seconds = (-6.2e-6 * tut1 * tut1 * tut1 + 0.093_104 * tut1 * tut1) * 283_104_000.0
        + (876_600.0 * 3600.0 + 8_640_184.812_866) * tut1
        + 67_310.548_41;

    // Reduce to one day, then to one turn.
    let mut degrees = (seconds % SECONDS_PER_DAY) / 240.0;
    degrees %= 360.0;
    if degrees < 0.0 {
        degrees += 360.0;
    }
    Ok(degrees * DEG_TO_RAD)
}
```

> **Note:** the `283104000.0` factor is `86400 * 3276.8`, the conversion from the cubic and
> quadratic coefficients in seconds to the same units; write it in the code as
> `(-6.2e-6 * tut1 * tut1 * tut1 + 0.093_104 * tut1 * tut1 + (876_600.0 * 3600.0
> + 8_640_184.812_866) * tut1 + 67_310.548_41)` and take the whole bracket modulo a day. The
> split above is only to keep the intermediate from overflowing in readability; the test
> against the reference value decides whether it is right.

```rust
//! Converting the state vectors SGP4 produces into frames the rest of the product uses.
//!
//! SGP4 is defined in TEME, the True Equator Mean Equinox frame: it shares the true equator
//! with the equator-of-date frame but takes the *mean* equinox, so it differs from TOD by
//! exactly the equation of the equinoxes. Getting back to an inertial frame therefore means
//!
//! ```text
//! r_GCRF = P * N * E^T * r_TEME
//! ```
//!
//! where `E` is a rotation about the z axis through the geometric part of the equation of the
//! equinoxes, `N` is nutation and `P` is precession.
//!
//! Source: Vallado, *Fundamentals of Astrodynamics and Applications* (2013), Algorithms 23
//! and 26 and eq. 3-77.

/// TEME to GCRF: the inertial frame the rest of the product works in.
///
/// # Errors
///
/// Returns [`Error::Invalid`] for a non-finite time.
pub fn teme_to_gcrf(ttt: f64, state: &CartesianState) -> Result<CartesianState> {
    let angles = precession::iau_1977_angles(ttt)?;
    let nutation = nutation::iau_1980(ttt)?;
    let mean_obliquity = nutation::mean_obliquity(ttt)?;

    // The equation of the equinoxes, geometric part only: TEME is defined against the mean
    // equinox, so this is the whole difference between it and TOD.
    let eqeq = nutation.longitude * mean_obliquity.cos();

    let to_gcrf = precession::iau_1976_matrix(ttt)?
        * nutation_matrix(nutation.longitude, nutation.obliquity, mean_obliquity)
        * Rotation3::about_z(eqeq).transpose();

    Ok(apply(to_gcrf, state))
}

```rust
//! The Earth-fixed conversion, `ITRF = W * R3(gmst) * r_TEME`.
//!
//! Two things make this more than one rotation. The Earth is turning, so a velocity measured
//! in the rotating frame differs by `omega x r`, which is why the velocity path crosses the
//! Earth rotation vector rather than just multiplying. And the sidereal angle used is the
//! *apparent* one when the kinematic equinox terms are included, which matters for dates after
//! 1997 -- see Vallado (2013), section 3.7 and the `eqeterms` flag in the reference routine.

pub fn teme_to_itrf(
    jdut1: f64, ttt: f64, eop: &EarthOrientation, terms: EquinoxTerms, state: &CartesianState,
